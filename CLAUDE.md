# Meet — P2P video meeting

Anonymous, room-code-based, peer-to-peer (WebRTC) video meeting.

## Architecture
- `frontend/` — static site (Vite + TS), built to `docs/` at repo root, served via GitHub Pages at `meet.itsash.in`. Landing page is only the code input + Join and a "New meeting" button, plus an OS-matched "Install for Mac/Windows" link (`bindInstallLink` in `ui.ts`, hidden on other OSes) to the latest GitHub Release assets `Meet.dmg` / `Meet.exe` (`DOWNLOAD_URL` in `config.ts`); Join and New meeting go straight into the call view (`#view-call`). There is no separate waiting screen: while alone, `setAlone(true)` in `ui.ts` shows `#waiting-panel` (share link + copy) in place of the partner tile and hides the call timer. Client-side signaling protocol/state machine runs in a Rust→WASM module (`frontend/wasm-signal/`, built with `wasm-pack`, output copied into `frontend/src/wasm/` — gitignored, regenerated by `make build`). Actual audio/video uses native browser WebRTC (`RTCPeerConnection`), STUN-only, no TURN.
  - Outgoing mic runs through a Rust→WASM voice enhancer (`frontend/wasm-audio/`: HPF → RNNoise → gate → leveler → presence EQ → compressor → limiter) inside an AudioWorklet (`frontend/src/enhancer-worklet.ts`), built with `cargo build --target wasm32-unknown-unknown` and copied to `frontend/src/enhancer/voice.wasm` (gitignored; kept out of `frontend/src/wasm/` because wasm-pack runs its old bundled `wasm-opt` on every `.wasm` in its out dir and that rejects the `trunc_sat` ops current Rust emits). The module has no imports, so the worklet compiles it synchronously from bytes in `processorOptions`. If the enhancer or AudioContext is unavailable, the raw mic is sent with browser noise suppression on (`AudioPipeline` in `rtc.ts`).
  - Compression: audio codec order RED → Opus (FEC + DTX), audio sender priority "high"; video codec order AV1 → H265 → VP9 → H264 → VP8.
- `desktop/` — pure-Rust native app (no HTML/CSS, no webview). UI: `eframe`/`egui` (`app.rs`: home = code input + Join and "New meeting"; call view, centered permission `Modal`, devices window; the self tile shows only while camera or screen share is on). `call.rs`: signaling actor on a tokio runtime with the same protocol, sid, heartbeat, backoff and recovery rules as `frontend/src/call.ts`, plus the `webrtc` crate peer connection. `media.rs`: `cpal` mic/speaker, the same `wasm-audio` enhancer crate (linked natively), Opus via `unsafe-libopus`, `nokhwa` camera, `xcap` screen share, `openh264` H.264. Only Opus + H.264 are offered, and the interceptor registry has no TWCC so browsers send REMB (bitrate from REMB with an RR-loss fallback). `perm.rs`: camera/mic access (AVFoundation on macOS, ConsentStore registry on Windows). `net.rs`: worker HTTP endpoints, share links use `PUBLIC_ORIGIN`. Calls start audio-only; the camera stays off until the user turns it on. `desktop/Makefile`: `run`, `app` (builds `dist/Meet.app` from `Info.plist` + `icons/icon.icns`, ad-hoc signs with `Entitlements.plist`), `run-mac` (`app`, quits a running `meet`, then `open`s the bundle so macOS asks for camera/mic as Meet, not as the terminal), `mac` (`app` + dmg with `diskutil image create from`), `windows` (tars `desktop/` + `frontend/wasm-audio/` to SSH host `pc` (cmd.exe shell, `~/meet`), runs `cargo build --release` there, copies the .exe back; `build.rs` embeds `icons/icon.ico`), `release` (`mac` + `windows`, then uploads them as `Meet.dmg` / `Meet.exe` to GitHub Release `v<version>` with `gh`, which the web install link points to); outputs land in `desktop/dist/` (gitignored).
- `worker/` — Cloudflare Worker + one Durable Object per room (`RoomSignal`), deployed to `meet-signal.its-ash.workers.dev`. Purely a WebSocket relay for SDP/ICE between exactly two peers. No media ever touches this Worker.
  - **Session lifecycle**: each connected socket must send `{"type":"ping"}` at least every 2s (client does this via `HEARTBEAT_INTERVAL_MS` in `frontend/src/call.ts`). The DO answers an exact ping with `{"type":"pong"}` via `setWebSocketAutoResponse` (no wake from hibernation); liveness = max(attachment `lastPingMs`, `getWebSocketAutoResponseTimestamp`). A recurring DO alarm sweeps every 2s and closes (code 4000) any socket idle (no message) for ≥10s; a new connection also evicts idle sockets before the room-full check. Each tab sends a per-tab `?sid=` (kept across refresh via sessionStorage); a new socket with the same sid replaces the old one at once (code 4001, client shows "open in another tab"). `/room-status/:roomId?sid=` excludes the caller's own and idle sockets. Per-socket `{lastPingMs, sid}` is stored via `ws.serializeAttachment()`, which survives DO hibernation.
  - Client (`frontend/src/call.ts`): signaling messages run one at a time through a promise chain; remote ICE candidates are buffered until the remote description is set; only the offerer does ICE restarts. The client never gives up: a dropped socket reconnects forever with capped backoff (`SOCKET_RETRY_*` in `config.ts`) and resets the peer connection; an OPEN socket with no traffic for `SOCKET_DEAD_MS` (after a first pong) counts as dead and is replaced; `online` / tab-visible events reconnect at once; a full room is polled every `FULL_ROOM_POLL_MS`; if media is not connected within `RECOVERY_TIMEOUT_MS` (doubling up to `MAX_RECOVERY_BACKOFF`, answerer waits 2×), the client rejoins the room. Signaling opens before the permission prompt resolves; the mic attaches later via `replaceTrack`.
  - When one peer disconnects, the survivor's socket is **not** closed — it receives a live `{"type":"peer-left"}` message and the client transitions back to `WaitingForPeer` (fresh 5s client-side "waiting for partner" countdown, separate concept from the server's per-socket heartbeat timeout).
  - A 3rd visitor to a full room is rejected with HTTP 409 at the WebSocket upgrade (`fetch()` in `room.ts`); the client avoids ever hitting this by calling `GET /room-status/:roomId` first (see `worker/src/index.ts`) and showing a "meeting is full" view if `count >= 2`.

## Conventions
- Root `Makefile`: `run` / `build` / `deploy`, coordinating `frontend/` and `worker/` (see Makefile itself), plus `run-mac`, which calls `desktop/Makefile`. Desktop builds live in `desktop/Makefile` and are not part of `deploy`.
- `docs/` at repo root is the GitHub Pages publish directory — regenerated by `make build`, committed on deploy. GitHub Pages is configured manually in repo settings (Pages → deploy from `docs/` on `main`); no GitHub Actions deploy workflow.
- `frontend/src/wasm/` and `frontend/src/enhancer/` are build output (gitignored) — never hand-edit, regenerate via `make build` (wasm-pack for `wasm-signal/`, cargo for `wasm-audio/`).
- Both `frontend/` and `worker/` are independent Node projects with their own `package.json`; `worker/wrangler.jsonc` binds the `RoomSignal` Durable Object and deploys to the default `meet-signal.its-ash.workers.dev` subdomain.
